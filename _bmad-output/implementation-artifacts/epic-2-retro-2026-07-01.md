## What Went Well

1. **The Epic 1 root-cause fix landed and retired a whole bug class.** Runtime contract-schema validation (TypeBox `Value` against the shared `@tlf/contracts` schema) was established in 2.1 and retrofitted across `getTodos`/`createTodo`/`patchTodo`; the hand-rolled `isTodo` guard — re-discovered in review across four separate Epic 1 stories — is gone. Highest-leverage move of the epic.
2. **"Establish-once, inherit-everywhere" paid off exactly as predicted.** The honest-pending seam and injectable `PendingClock` were reused verbatim — `useArmedDelete`'s 300 ms / 5 s timers ride the same clock as the flicker threshold, which made 2.3's race tests deterministic. The nested-`<label>` row laid down in 1.6 *specifically for delete* meant Epic 2 added only a sibling button, no row-markup rewrite.
3. **Scope discipline held under a compressed timeline — zero dead code.** 2.1 refused to add an `announce` param it wouldn't use; 2.2 refused early `aria-pressed`; each deferral named its target story (2.3 / Epic 3). When 2.3 needed them they slotted in cleanly.
4. **Reviews caught real bugs and the fixes stuck with regression tests** — strict-204 wrapper + stale-rollback removal (2.1), six patches (2.2), a stale-comment fix (2.3), each with a test.
5. **Container re-deploy honored the "re-deploy at each epic's end" discipline** — real Docker build/run + real-browser verification, not just a local `dist` serve.

## Challenges & Recurring Themes

1. **The delete-vs-toggle same-row race shipped in 2.2 and was only caught in 2.3.** 2.2's toggle guards checked `pending` but not `deleting`, so a Committing row was `aria-busy` yet still toggle-live — a keyboard Enter or tap could fire a PATCH racing the in-flight DELETE. 2.3 Task D1 closed it (`busy = pending || deleting`). Caught inside the epic (good), but this is the *same* async-mutation-race class that dominated 1.8/1.9 review patches, and Epic 1 action item 3 asked to bring those lessons into the 2.2 design up front. The *timing* races got that treatment; this *cross-mutation* race slipped through 2.2's design and review anyway.
2. **The bundle-size ratchet generates rebaseline churn, not regression catches.** 2.1 rebaselined +14 KB (the accepted TypeBox runtime-validation cost); 2.2 rebaselined +725 B. Nearly every story trips it and we rebaseline. It is doing paperwork, not gate-keeping.
3. **LiveRegion identical-consecutive-message limitation resurfaced** — deleting two same-named tasks announces once (shared with create/toggle). Correctly deferred to 3.2, but now an explicitly-carried a11y gap.
4. **Node 24 ABI friction persists** — `nvm use 24` still required for API tests (recurring from Epic 1). Mitigated by `.nvmrc` + project memory, not eliminated.
5. **Action-item follow-through was uneven** (see scorecard). The commitments that slipped were the cross-cutting / "optional" ones with no named story slot.

## Key Insights

- **Retro action items survive when they have a named story home.** Item 2 succeeded because it was scoped to "establish in Story 2.1"; item 5 succeeded because it was closed inside the retro. Items 4, 6, 7 evaporated because they had no slot to land in. The process fix is structural: give every action item a target story or a `deferred-work.md` entry.
- **New per-row mutations must be audited against *all* existing row guards, not just their own path.** The delete-vs-toggle gap was a state (`deleting`) that a sibling guard (`pending`) didn't know about.
- **The P0 delete interaction still has no committed regression net.** Hook/jsdom coverage + injectable-clock race tests are strong, but the real-browser arm→confirm→revert timing/focus behavior was verified *once, manually* (Playwright/Chrome DevTools MCP as an investigation aid). No committed spec, no CI `e2e` job. Epic 3's browser-level a11y gates (3.3) cannot start until this harness exists.

5. **Every retro action item gets an explicit target story or a `deferred-work.md` entry.** No slot-less commitments — this is the structural fix for the 3-of-7 evaporation. Owner: facilitator/dev at retro close.

**Debt (resolve, don't carry a third epic)**

6. **Settle the nested-`<label>` DOM decision in Story 3.1.** Roving tabindex already touches the row-anchor DOM, so it's the natural moment: either fix the label-in-label or formally record the re-accept (zero axe violations) in `deferred-work.md`. Do not carry it implicitly again. Owner: dev/architect at 3.1.
7. **Bundle-size ratchet → absolute NFR budget check.** Convert the per-story ratchet (which always trips → rebaseline) into a fail-only-if-over-budget gate when Story 3.4 reworks CI gates. Owner: dev.

**Team agreements**
