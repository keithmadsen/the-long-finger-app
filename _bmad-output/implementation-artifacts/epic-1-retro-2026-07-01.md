## Challenges & Recurring Themes

1. **Response shape-validation gaps recurred across four stories** (THE recurring finding):
   - 1.1 — web trusts `/todos` JSON without checking it is an array
   - 1.6 — malformed successful `/todos` payload can crash rendering instead of the load-failed path
   - 1.7 — successful `POST /todos` JSON is cast, not shape-validated
   - 1.8 — `patchTodo` accepts a valid Todo response for the *wrong id*

   The `isTodo` guard emerged in 1.7 and was reused in 1.8, but the *need* was re-discovered in review each time rather than applied by default at every new network touch.
2. **Async races in the mutation layer were the most bug-dense area.** 1.8 (per-row arbitration racing before `togglingIds` updates; optimistic title before PATCH confirmed) and 1.9 (late settlement corrupting an active retry; refetch removing the optimistic row before failure handling; duplicate rows after commit-with-client-failure) generated the bulk of the review patches.
3. **A UX-spec contrast contradiction surfaced only during implementation** (1.6): the muted token could not be simultaneously ~AAA on the surface and ≥3:1 distinct from active text. Deferred to 1.7 and resolved by decoupling into a dedicated `--color-pending` token.
4. **Node 24 ABI friction** recurred: the shell defaults to Node 22, but `better-sqlite3`'s native binary is Node 24 ABI — backend tests require `nvm use 24`. (Mitigated by `.nvmrc`.)
5. **Nested-label row DOM is technically invalid HTML** (label-in-label), carried deliberately from 1.6 through 1.8 as accepted debt (zero axe violations). Flagged repeatedly.
6. **Epic 1 was oversized relative to Epics 2 & 3** (11 stories vs 3 vs 5) — it front-loaded all one-time foundation *plus* the feature loop. The thin-slicing absorbed the size well, but the imbalance is a real planning observation.

---

## Key Insights

- A greenfield **foundation epic will always be oversized**; the mitigation is thin, dev-agent-sized stories, not a balanced story count.
- The recurring shape-validation bug has a **root-cause fix already in hand**: `@tlf/contracts` exports the TypeBox `todoSchema`. Validating API responses against the *shared contract schema* at every client wrapper gives the guard for free, in both directions, and can't drift from the server.
- Epic 2's arm-then-confirm delete is the **highest-risk interaction in the app** — timing-heavy (300ms no-commit + 5s auto-revert) — i.e. exactly the class of bug that dominated 1.8/1.9 review patches. The race lessons must feed the 2.2 design *before* coding.

| Tool | Decision | Rationale |

The drift Pact prevents cannot occur here; it would add a broker + provider-verification job + vitest FFI-safety config for no gain. Revisit only if the API is split into an independently-deployed service or an uncontrolled third-party consumer appears. |
